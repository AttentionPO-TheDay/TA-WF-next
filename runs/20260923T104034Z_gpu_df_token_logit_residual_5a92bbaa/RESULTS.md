# DF 原分类头＋生成 token 类别分数残差：结果

状态：completed。三条件×三 seed×45 epochs 全部完成；RTX 4090 GPU0，总耗时168.19秒。训练和推理均保留生成 token；独立 `verify.py` 核验无错误。

## 结论

预定两关只过了弱的 token 归因关，没有通过部署准入。`residual_window` 相对同结构、同参数 `residual_constant` 的 valid macro-F1 三 seed 均值仅 +0.142pp（2/3 seed正），五个 TemporalDrift 开发日期均值差全部正；按事先写定的严格不等式，token 归因候选门槛通过。但第一 seed 的 valid 差为 −3.329pp，正向幅度小且不稳定，不能把它说成稳健增益。

相对本轮原始 `df_only`，`residual_window` valid macro-F1 **−2.790pp**，三 seed 全负；五个开发日期均值也全部负，部署候选门槛明确失败。保留原始 DF 分类头、零初始化类别修正并没有阻止后续训练退化。与上一轮局部特征残差相比，本轮也没有提供更强证据；不应继续凭同一开发 valid 反复寻找更好的修正层。

## 权限、核验与解释

复用固定 TemporalDrift source2040、valid510、五未来日期各2040行；只取前5000包方向，宽50/250的有序window token、partial中和和full-source统计标准化。source标签只训练，valid只选epoch，未来日期仅在选模后用于已观察数据的开发评分。`PLAN.md`、`config.json` 和训练代码在启动前冻结；输入依赖散列在 `artifacts/input_seal.json`。未读取 WTT-Time/AWF，未加载旧项目 checkpoint；原始数据只读。

独立 `verify.py` 重建输入与标准化、核对固定行号及source/valid方向重复为0、检查最早最佳epoch和同seed初始化，并重载63组checkpoint复算全部预测和指标；错误0，见 `artifacts/integrity.json`。

本轮是受上一轮开发反馈影响的新方法版本，TemporalDrift valid和未来日期已多次用于选择机制；小的 token−常量正差可能受开发集反复试验影响，不是独立确认。DF-only 本轮 valid 48.144%，与前轮从头训练的46.264%不同，跨轮数值不应当作架构效果的严格配对；本轮结论以同轮预定对照为准。下一步更合理的是停止在这套固定小开发集上继续调 DF-token 结构，整理候选与失败模式；如要作外部评价，需先冻结一个满足部署准入的候选并审计 WTT-Time/AWF 权限，不能将本轮失败版本送去试未来集再返调。
