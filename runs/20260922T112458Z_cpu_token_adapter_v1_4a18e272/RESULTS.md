# 实验结果

完成：冻结生成器规则、coarse run token，比较无适配器与轻量残差适配器；三条件×3 seed、source2040/valid510、15 epochs、CPU3线程。耗时2分08.31秒，峰值RSS约2.16 GiB，无GPU/未来/WTT/AWF访问。

## 结果

单位%，均值±样本SD；valid macro-F1选模，平局最早。

| 条件 | accuracy | macro-F1 | 参数 |
|---|---:|---:|---:|
| baseline：无适配器 | 22.94±0.98 | 20.87±0.81 | 79558 |
| adapter_zero：32→8→32残差，末层零初始化 | 23.07±1.45 | 20.90±1.30 | 80110 |
| adapter_random：相同结构随机初始化 | 22.48±0.88 | 20.60±0.97 | 80110 |

adapter_zero相对baseline的逐seed macro-F1差为 -0.301/+0.629/-0.221pp，平均仅+0.036pp；accuracy平均+0.131pp；未通过预设的“三seed F1均正且accuracy均值正”门槛。adapter_random相对baseline三seed F1均为负，平均-0.270pp，说明随机初始化没有帮助。zero相对random平均F1+0.306pp，但三seed并非全正，不能单独据此证明零初始化适配器有稳定收益。

适配器并非没有学习：零初始化版本下投影首步梯度为零是末层全零的预期，上投影首步即可获得梯度；第二步下投影梯度测试通过，三个checkpoint的上投影权重范数约0.909/0.901/0.786。这个结果只说明适配器能够从恒等起点被训练，未说明它能提高泛化。

## 结论

第一步不支持在当前source/valid、15epoch和coarse token设置下默认加入该小适配器。更准确地说，适配器结构和初始化可运行，但三seed收益不稳定且均值接近零；不能因为没有正向结果就否定“冻结生成器＋适配器”的整体方向。下一步若继续，应优先把适配器放在run/window各自分支上并做容量匹配，或增加预先固定的训练预算检查收敛；不要根据这次valid结果在线更新生成器。

本轮训练的是“生成器冻结、主模型和适配器联合训练”，不是冻结主模型只训练适配器，也不是漂移后的在线适配。未来要研究“根据漂移效果进化”，须另立明确的历史/未来数据权限、更新频率、标签预算和回滚规则；本轮没有读取漂移日期。

## 核验与限制

9指标、4590条预测独立重算；checkpoint重载、选模、hash、输入隔离、padding、初始恒等、第二步梯度和coarse-only权限通过。全仓库35测试通过1跳过。生成器规则逐条固定，适配器参数仅在模型训练中更新；没有加载旧目录checkpoint或训练代码，仅使用旧虚拟环境依赖。每类source20/valid5，valid已多轮开发，三seed不足以作显著性、独立确认、抗漂移或最终模型结论。
