# 实验结果

状态：completed。RTX 4090 GPU 0 训练，固定 TemporalDrift source 2040、valid 510、五日期各 2040 行。三条件×三训练 seed×45 epochs，均为同一 219494 参数模型，输入权限以真实/常量分支控制；训练和推理均保留分支。运行约 60.4 秒（含数据生成与评分）。未来日期仅在 valid 选模后作开发评分。

fusion 相对 packet-only 的 valid 三 seed 差为 +7.450/+8.487/+9.110pp，五日期所有 15 个 seed×日期配对均正。fusion 相对最强单视角 window-only 的 valid 三 seed 差为 +4.178/+2.656/+2.357pp；五日期 13/15 配对为正，只有 seed 3407 的 Day90 −0.327pp 和 Day150 −0.120pp。两个事先设定的候选门槛均通过。accuracy 同样逐角色记录在 `artifacts/metrics.csv`；valid 均值 27.647/31.569/34.314%。

这给出本项目首个较直接的正向证据：由生成器构造的 window token 经专属处理层，在当前 GPU 主模型中提升了分类表现，且融合超过了任一单视角。相同原始方向输入、相同总参数、相同训练清单及训练预算支持将增益解释为有用的表示和编码归纳偏置，而非新增原始信息；常量分支的有效容量较低，故不能宣称严格等有效容量。

## 泛化与漂移限制

从 valid 到 Day270 的 F1 下降：packet-only 11.053pp、window-only 12.391pp、fusion 14.406pp。fusion 的绝对 F1 始终较高，但随时间下降也更大；本轮不支持“生成器本身缓解漂移”的说法。用户设想中漂移影响由其他模块缓解，本轮没有测试该模块或漂移后 adapter 更新。

本轮 token 专属层在训练和推理时都使用。若最终部署只允许生成器在训练阶段参与，需另做蒸馏/训练期监督实验，不能把本轮融合分支直接移除后沿用这些分数。TemporalDrift source/valid 和未来日期已参与多轮方法开发，本轮不构成独立确认，也不能据三 seed 做跨数据集显著性主张。后续冻结方法前仍需检查更强 packet backbone、训练样本规模及外部数据权限。

第 45 轮训练 accuracy 均值约 packet 42.5%、window 70.8%、fusion 81.1%；融合增益不能仅归因于训练集拟合，因 valid 与五日期亦有正向绝对 F1。所选 epoch：packet 42/45/34，window 39/43/44，fusion 44/41/38。后段仍可能过拟合，不能无限延长轮数。
