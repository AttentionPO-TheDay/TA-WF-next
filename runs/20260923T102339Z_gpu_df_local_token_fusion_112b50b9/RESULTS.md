# DF 局部多尺度 token 融合：结果

状态：completed。上一轮扁平 MLP 末端拼接的阴性反馈之后，按本轮 `PLAN.md` 预先冻结的新处理器训练三条件×三 seed×45 epochs；RTX 4090 GPU0，总耗时151.96秒。训练与推理均保留真实生成 token。输入、选模、预测和 checkpoint 独立核验通过。

## 结论

预定的局部 token 候选门槛**通过**：`local_window` 相对同结构同参数的 `local_constant`，valid macro-F1 三 seed 均值 +1.216 个百分点、3/3 seed正；五个 TemporalDrift 开发日期的均值差有4/5为正，五日期差的平均亦为正。这是生成器在 DF 专属局部处理器中产生可测增量的开发证据，与上一轮末端拼接的 −11.006pp 阴性结果不同。

但尚无相对成熟 DF 的**部署收益**：本轮 `local_window` valid macro-F1 46.110%，原始 `df_only` 46.264%；五日期中只有 Day150 略高，Day270 反而低0.562pp。token 分支主要补回了同结构常量处理器相对 DF 的损失，不足以说它让 DF 整体更好。预定候选门槛只检验真实 token 相对常量分支的归因，不等同于超过原始 DF 的准入门槛。

## 方法与核验边界

固定复用 TemporalDrift source2040、valid510、五日期各2040行及前5000方向；生成宽50/250的有序 window token，partial 中和，用 full source 统计标准化。两组独立局部卷积把100和20个 token 对齐到 DF 的18位置局部特征图，再通过零初始化、系数0.1的残差接入原 DF classifier/head。`local_constant` 接收全零标准化 token，隔离附加处理层的影响；原始 DF 是强部署参照。数据标签权限、冻结配置和停止条件详见 `PLAN.md`、`config.json`。

独立 `verify.py` 核对输入散列、固定行号、source-only标准化、source/valid方向重复为零、每条件最早最佳 epoch、63次checkpoint预测重算及63行指标，无错误（`artifacts/integrity.json`）。未加载旧项目 checkpoint，未访问 WTT-Time/AWF；原始数据只读。

本轮设计是看到上一轮阴性反馈后登记的新版本，同一 TemporalDrift valid 与未来日期均已反复用于开发，不能把本轮候选通过写成独立确认或已成熟的 DF 改进。与上一轮相较同时改变了处理器拓扑、融合位置和分类头保留方式，不能单独归因于“保序”或“零初始化”。若后续继续，应预定明确的部署准入标准（必须胜过原始 DF）及有界验证，而不是围绕同一 valid 追调结构后只保留成功结果。
