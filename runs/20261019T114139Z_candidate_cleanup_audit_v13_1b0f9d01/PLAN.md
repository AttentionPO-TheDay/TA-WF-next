# 候选清洗审查 v13

问题：v12 的低 NAR 纠错增益为何未转化为 Version 候选纯度改善？新增接纳的污染来自接纳数量、特定类别，还是辅助证据只否定旧类而未确认新类？

范围：已观察的 version_045、network_USA；源 seed 42/100/2026，继承固定 query/sourcevalid 行清单。源 valid 仅作诊断对照，跨切片重复不算独立重复。不重新划分、不访问原始共享数据、WTT/AWF 或模型 checkpoint。

权限：只读 v9/v10/v11/v12 缓存和冻结源校准；query 标签只用于终端错误分类、原阈值重算、前沿和可分性诊断。诊断结果不能直接拟合、选取或部署新评分器。本轮零训练、零新前向、零校准拟合。

冻结对照：v9_margin 与 v12 margin_plus_soft；候选恒为 v9 smooth_balance Top1。使用 v12 已记录的 NAR≤1% 操作点，不按本轮信号重新选阈值。阈值本身是 query 标签选出的诊断操作点，无部署保证。

步骤一：逐行分解共同接纳、新增接纳、移除接纳、共同拒绝；分别统计真纠错 R、负适应 D、旧错→其他错 W。输出真实/旧/候选类别分布、前五类集中度和新增候选的辅助视图获胜类别。独立重算 v12 主指标计数。报告同原基线实际 NAR 预算、同基线纠错数的最小前缀（约束 NAR≤1%），完整保存两评分的确定性 C/D/W 前沿，不拆同分组；只作诊断比较。

步骤二：从已有三 seed×五视图、原 v10 温度和 v12 权重提取固定信号：候选平均概率、候选平均 log 概率、否定旧类(-平均 log 概率)、候选相对第三类裕度、候选相对任意竞争类裕度、候选投票比例、负 logodds 标准差、平均 logodds。第三类排除 frozen 类及候选类；所有特征方向预先固定为越大越支持接纳，不用 query 标签翻转。

固定诊断集合：全部 changed、两评分接纳并集、新评分新增接纳、接纳边界。边界为两评分各自阈值在 changed 降序排列中前后 max(25, ceil(.10*N_changed)) 个位置的并集，完整保留边界同分。边界由已有操作点定义，是标签条件化诊断集合，不是新门控规则。

指标：R vs W 和 R vs D 分别计算描述性 AUROC、AP/正例基率、FPR≤.01 的 raw/alpha pAUC。另按集合内原 v9 裕度或 v12 主分数的无标签十分位分层，计算只含同层正负对的 AUROC，并记录正负样本数、可比对数/覆盖；不跨层比较。样本不足（R 或对照少于20）标记 limited。该 AUROC 只定位失败机理，不作为评分选择替代低 NAR 目标。

解释原则：仅当候选确认信号在两个切片的边界内分层 AUROC 都一致优于随机、且不是单一 seed 驱动，才视为可继续验证的线索；不据此宣称已实现清洗。若不稳定，如实停止评分项堆叠。源 valid 与目标的差异也需完整报告，不以源域可分性保证目标可分性。无显著性检验、无训练或外部有效性结论。

预算：CPU 2线程，墙钟≤600秒，输出≤0.25 GiB，GPU 0小时；只跑这一固定分析批次。输入散列及代码/配置在分析前冻结；失败保留日志，修错不得借机改特征/阈值。

交付：RESULTS.md、逐 seed 计数与边界表、类别集中度、逐行特征与接纳掩码、完整前沿、诊断图及独立审核。修改 STATUS.md 当前事项，旧 run 不变。
