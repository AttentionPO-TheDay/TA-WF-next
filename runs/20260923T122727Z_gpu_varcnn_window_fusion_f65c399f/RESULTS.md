# VarCNNDirection 直接融合 window token：结果

状态：completed。三条件×三 seed×45 epochs 全部完成；GPU0耗时280.89秒。独立核验重建63个checkpoint预测和指标，错误0。

## 结论

真实 window token 相对同结构常量-token 融合分支的归因门槛通过：valid macro-F1 均值 +1.971pp，2/3 seed 为正（逐 seed +3.527/+2.744/−0.359pp）；Day14/30/90/150/270 均值差全部为正（+1.291/+1.558/+1.724/+2.081/+2.771pp）。这说明 window 生成器特征在 VarCNNDirection 的当前分支中包含可学习信号，但 seed 稳定性并非完美。

但部署准入失败：真实 window 模型 valid macro-F1 18.107%，原始 VarCNNDirection 为27.190%，差 −9.082pp；五日期也全部低于原始 VarCNNDirection，平均差 −6.441pp。因此不能把 VarCNN 的这一接法作为第一版主模型，也不能把 token 归因正向误写成整体模型收益。主要问题是两种融合模型都显著损伤原始主干，常量控制本身 valid F1 仅16.137%。

## 限制与下一步

VarCNNDirection 是本项目明确标注的方向单分支派生版本，不等同于原始双分支 VarCNN。当前融合头是全局拼接，不是局部对齐；训练从头、batch64、45轮，原始主干在source上几乎完全拟合而融合条件拟合较差，提示额外分支改变了优化/容量平衡。该阴性结果不能说明生成器与 VarCNN 所有接法都无效，但已说明“直接加一个大拼接头”不适合作为第一版。若继续，应先设计零初始化、保留原分类路径的受控残差接入，并预先要求超过原始 VarCNNDirection；不要在同一开发集上继续堆叠普通融合层。

独立 `verify.py`：source/valid方向重复0，输入/标准化散列一致，63次checkpoint预测重算、63行指标和最早最佳epoch核对无错误，见 `artifacts/integrity.json`。
